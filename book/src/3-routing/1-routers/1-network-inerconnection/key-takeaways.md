# Основные выводы

Для выполнения задания по объединению подсетей необходимо:
- на маршрутизаторе настроить IP-конфигурацию для каждого интерфейса, например при помощи следующих команд:
    ```sh
    R1# configure terminal
    R1(config)# interface Ethernet 0/0
    R1(config-if)# ip address 192.168.1.254 255.255.255.0
    R1(config-if)# no shutdown
    R1(config-if)# exit
    ```
- на хостах задать IP-адрес, маску подсети и маршрут по умолчанию, например:
    ```sh
    root@PC1:~# ip address add dev eth0 192.168.1.1/24
    root@PC1:~# ip route add default via 192.168.1.254
    ```
    
    ::: warning Внимание
    IP-конфигурация Linux-хоста при помощи утилит из пакета `iproute2` (т.е. `ip address add ...`, `ip route add ...`) будет действовать до перезагрузки устройства.
    Для постоянной конфигурации необходимо применять другие способы. Например, при помощи конфигурационного файла `/etc/network/interfaces`, как будет показано в задании [Статическая маршрутизация](/3-routing/1-routers/2-static-routing)
    :::

Для определения технического состояния применяются следующие утилиты:
- `ping`, который показывает базовую доступность:
    ```sh
    root@PC2:~# ping 192.168.1.1 -c 3
    ```
- `traceroute`, который отображает путь пакетов и помогает локализовать проблемы:
    ```sh
    root@PC1:~# traceroute 192.168.2.1
    ```
- `tcpdump`, который позволяет анализировать проходящий на хосте сетевой трафик в реальном времени:
    ```sh
    root@PC2:~# tcpdump -i any
    ```
